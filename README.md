# ROUTE RACE — 길찾기 전략 실험실

[공개 페이지](https://hyungminyoon1.github.io/route-race/) · [WEB LAB](https://hyungminyoon1.github.io/web-lab/)

같은 지도에서 BFS·Dijkstra·A*·Weighted A*의 경로 비용과 확장 기록을 비교합니다. 이 변경의 로컬 검사와 공개 배포 증거는 [검증 기록](docs/verification.md)에서 구분합니다.

## 도전과 미션

- 도달 가능한 다섯 시드 지형: 싼 우회로(비용 함정), 막다른 미로, 엇갈린 관문(병목), 거리의 유혹, 구조된 황야(혼합 지형).
- 새 시도는 브라우저 crypto로 새 uint32 시드를 선택합니다. 고정 시드 증가 패턴을 사용하지 않습니다. `RR1-maze-2026`처럼 원본 재현 코드로 같은 지도를 복원할 수 있습니다. 다른 시드가 같은 유한 지형을 만들 수는 있습니다.
- 비교 예측: 짧은 경로의 비용, A*의 확장 수, Weighted A*의 비용 손실을 먼저 예측하고 실제 수치로 피드백을 받습니다. 탐색 계산 시 예측이 잠깁니다. 예측 없이 관찰하는 것도 가능합니다.
- 설계 미션: 빈 지도에서 S/E를 유지하고 1~8칸을 바꾸어 BFS 비용이 Dijkstra보다 8 이상 높게 만드세요. 미션은 순수 모델의 실제 비용 차이·편집 수·도달 가능성으로 판정합니다. 임의의 난이도 등급이나 점수는 없습니다.
- 힌트와 성공/재조정/경로 없음 피드백. 편집·가중치 변경은 이전 예측과 결과를 폐기합니다.

## 탐색 근거 읽기

한 단계는 하나의 칸을 꺼내 확장하는 기록입니다. 옅은 색은 확장한 칸, 점선은 후보, 검은 테두리와 점은 현재 칸, 진한 색은 완료 경로입니다. 각 전략 아래에서 꺼낸 칸의 g/h/우선값, 후보 수, 새 발견·개선한 경로, 다음 후보 상위 5개를 읽습니다. 후보 전체 위치는 지도에 표시합니다. 종료 시 남은 후보는 이후 탐색하지 않습니다.

| 전략 | 다음 후보 선택 | 보장 |
| --- | --- | --- |
| BFS | 선입선출, g는 이동 횟수 | 최소 이동 횟수. 최소 비용은 보장하지 않음 |
| Dijkstra | 최소 누적 진입 비용 g | 최소 경로 비용 |
| A* | 최소 g + 맨해튼 거리 h | 최소 경로 비용 |
| Weighted A* | 최소 g + wh, w=1/1.5/2/3/4 | w=1이면 A*와 동일. w>1은 최적 비용 보장 없음 |

상하좌우 이동, 출발 칸 제외. 평지 1, 자유 편집 험지 2~99 정수; RR1·설계 미션은 비용 1/5를 유지합니다. 이웃은 오른쪽→아래→왼쪽→위 순서로 발견하고, 동률은 먼저 발견한 후보부터 처리합니다. 닫힌 칸은 재확장하지 않으며 도착 칸을 꺼내면 종료합니다. 최소 진입 비용이 1 이상이므로 기본 A*의 맨해튼 추정은 허용 가능하고 일관적입니다. Weighted A*에는 근사 비율을 주장하지 않습니다.

확장 수와 최대 후보 수는 이 구현에서의 작업량입니다. 같은 간격의 애니메이션 재생은 **실행 시간 벤치마크가 아닙니다**. Weighted A*가 항상 비용이나 확장 수를 개선하는 것도 아닙니다.

## 편집과 재현

새 지도는 20×12입니다. 가져온 지도의 크기는 2~30열 × 2~20행까지 유지합니다. 벽·평지·험지·S/E를 클릭/드래그하거나 편집기에 Tab으로 진입한 뒤 방향키와 Space/Enter로 그립니다. 험지 비용 변경은 이후 그릴 칸에만 적용됩니다. 최근 32단계 편집·가져오기를 지도/설정과 함께 되돌릴 수 있습니다. 기본 지도·빈 지도·원본 다시 시작, 재생·정지·한 단계·슬라이더·결과 보기를 제공합니다. 동작 줄이기 설정에서는 자동 재생을 시작하지 않습니다.

- `RR1-maze-2026`은 기존 원본 생성 코드입니다. w는 별도로 선택합니다. 생성 규칙은 변경하지 않았습니다.
- `RRM1-{"version":1,...}`은 전체 편집 지도·크기·모든 칸별 비용·S/E·그릴 험지 비용·Weighted A*의 w를 담는 코드입니다. "지도 코드 내보내기 · 가져오기"에서 코드 만들기/복사/붙여넣기/가져오기를 사용합니다. 같은 지도의 모든 실제 탐색 결과와 추적 순서를 재현합니다.
- 최대 ASCII 8192자. 버전·정확한 필드·자료형·2~30×2~20 크기·타일 개수·비용·벽이 아닌 S/E·설정 범위를 검증합니다. 잘못된 코드는 지도를 바꾸지 않습니다. 경로 없음과 S=E도 유효한 지도 상태입니다.
- 복사 버튼에서만 클립보드에 쓰고 자동 읽기나 업로드는 없습니다. 가져온 지도는 독립 완료로 인정하지 않습니다. 예측·결과·되돌리기는 코드에 포함하지 않습니다.

## 기기 완료 기록

기존 설계 미션(빈 20×12, 고정 S/E, 비용 1/5, 편집 1~8칸, BFS−Dijkstra 비용 차이 ≥8)을 힌트·예제·가져오기 없이 직접 완료하면 1/1을 기록합니다. 예측 정답이나 방문 수는 완료 수가 아닙니다. `route-race-achievement-v1`에는 성공 지도 하나만 저장하고 새로고침 때 실제 탐색과 미션 조건을 재검증합니다. 코드 가져오기·도구를 통한 편집/계산은 완료 기록 대상에서 제외됩니다.

갤러리는 `web-lab-progress-v1`의 `{version:1,apps:{"route-race":{completed,total,updatedAt}}}`만 읽습니다. 15개 허용 ID, 최대 8192자, `0≤completed≤total≤1000`, ISO UTC 시각을 검증합니다. 지도·시드·행동·이름은 요약에 없습니다. 최초 방문은 기록하지 않고 기존 완료의 날짜도 새로고침만으로 바꾸지 않습니다. "기기 완료 기록 → 완료 기록 지우기"는 이 앱의 성공 지도와 자체 요약만 제거합니다. 개인 저장 지도 목록은 추가하지 않았습니다.

## 로컬 실행과 검증

Node.js 22 이상. 외부 런타임 패키지·외부 자산은 없습니다.

```sh
npm run dev -- 0
npm test
npm run check
```

- LOCAL: 독립 Bellman–Ford 오라클로 다섯 도전×120시드=600개, 별도 생성 180개, 새 비용 1~99 지도 60개를 대조합니다. 전체 지도 코드 왕복·엄격한 입력 거절·합법 설계 해법과 실패 조건·독립 완료 제외 조건·저장 실패·다른 앱 요약 보존/자체 삭제를 검사합니다.
- 브라우저 조작, 화면 QA, 원격 CI와 공개 페이지는 별도 증거입니다. 실행한 흐름과 제한은 [검증 기록](docs/verification.md)을 확인하세요. 모델 테스트를 브라우저 또는 공개 배포 검증으로 간주하지 않습니다.

계산 모델과 UI가 분리되어 있습니다. 지도 생성과 탐색은 시드에 대해 결정적이며, 시드 선택만 UI에서 이루어집니다. 모델 최대 30×20, 각 전략 최대 V칸 확장, 후보 스냅샷 최대 O(V²), 단계당 상위 5후보/4갱신, 되돌리기 최대 32지도, 재생 중에만 프레임을 예약합니다.

편집 상태는 새로고침하면 초기화되고 완료 기록만 기기에 남습니다. 서버·백엔드·계정·쿠키·업로드·방문자 추적·실행 중 외부 API 요청은 없습니다. 저장 실패 시 계산은 계속 사용할 수 있습니다. 기기 기록은 사용자가 수정할 수 있고 동일 출처 앱 간 기술적 격리는 없으며 공개 순위가 아닙니다. 기존 GitHub 호스팅 로그와 앱 데이터 처리는 별개입니다.
